# commit: 변경사항 분석 후 컨벤션 커밋

현재 작업 디렉토리의 git 저장소에서 변경사항을 분석하고, 논리적 단위별로 한국어 커밋 메시지를 작성해 **승인 절차 없이 바로 커밋**한다. 사용자는 커밋 승인을 사전에 위임했다.

## 워크플로우

### Step 0: 저장소 지침 확인

저장소 루트의 `AGENTS.md`(없으면 `CLAUDE.md`)에 커밋 관련 규칙이 있으면 이 스킬보다 우선해 따른다. 최근 커밋 기록(`git log --oneline -10`)이 있으면 실제 사용 중인 스타일도 참고한다.

### Step 1: 변경사항 수집

다음을 실행해 전체 변경 범위를 파악한다.

```bash
git status --short
git diff --stat
git diff              # unstaged 변경
git diff --cached     # 이미 staged된 변경
```

- untracked 파일은 `git diff`에 나오지 않으므로 `git status`로 확인하고, 필요하면 파일 내용을 직접 읽어 성격을 판단한다.
- 변경사항이 없으면 사용자에게 알리고 종료한다.
- 이미 staged된 변경이 있으면 그 범위를 먼저 하나의 커밋 단위로 취급하고, 나머지 변경은 별도로 분류한다.

### Step 2: 커밋하면 안 되는 파일 걸러내기

다음에 해당하면 커밋 대상에서 제외하고 사용자에게 경고한다.

- 비밀정보: `.env`, `*.pem`, `*.key`, 자격증명·토큰이 들어 있는 파일
- 빌드 산출물·의존성: `node_modules/`, `dist/`, `build/`, 캐시 디렉토리
- 대용량 바이너리나 개인 로컬 설정 파일

`.gitignore`에 추가가 필요해 보이면 제안만 하고, 임의로 수정하지 않는다.

### Step 3: 논리적 단위로 분류

변경사항을 "하나의 목적" 기준으로 묶는다. 파일 단위가 아니라 **의도** 단위로 나눈다.

- 기능 추가와 버그 수정, 리팩터링, 설정 변경이 섞여 있으면 별도 커밋으로 분리한다.
- 한 기능을 위해 함께 바뀐 코드·타입·테스트는 같은 커밋에 둔다.
- 한 파일 안에 성격이 다른 변경이 섞여 있으면 가장 비중이 큰 목적의 커밋에 함께 넣고, 최종 보고에 그 사실을 알린다(`git add -p`는 대화형이라 사용할 수 없으므로 파일 단위 분리를 기본으로 한다).
- 변경이 작고 목적이 하나뿐이면 커밋 하나로 충분하다. 억지로 쪼개지 않는다.

### Step 4: 커밋 메시지 작성

형식:

```
<type>: <요약>

<본문 (선택)>
```

type:

| type | 용도 |
|------|------|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 코드 구조 개선 |
| `chore` | 빌드·설정·의존성·문서 등 기타 작업 |

작성 규칙:

- 요약은 **한국어**로, 50자 이내, 마침표 없이 쓴다. 명사형 종결(예: "추가", "수정", "개선")을 사용한다.
- "무엇을 바꿨는지"보다 "왜/무엇을 위해"가 드러나게 쓴다.
- 변경 이유나 맥락이 요약만으로 부족할 때만 본문을 추가한다. 본문은 빈 줄 하나 뒤에 한국어로 쓴다.
- 시스템이 지정한 커밋 attribution 줄(예: `Co-Authored-By`)이 있으면 메시지 끝에 붙인다.

예시:

```
feat: 컴포넌트 생성 시 Props 타입 자동 추론 추가
fix: 빈 입력으로 생성 요청 시 서버가 500을 반환하던 문제 수정
refactor: 프롬프트 빌더를 템플릿별 모듈로 분리
chore: ESLint 설정에 React Hooks 규칙 추가
```

### Step 5: 커밋 계획 안내

커밋 계획을 다음 형식으로 보여준다. **승인을 기다리지 않고** 바로 Step 6으로 진행한다.

```
커밋 1/2
  메시지: feat: 컴포넌트 미리보기 패널 추가
  파일:
    - src/components/PreviewPanel.tsx
    - src/App.tsx

커밋 2/2
  메시지: chore: vite 개발 서버 포트 설정 변경
  파일:
    - vite.config.ts

제외: .env (비밀정보 의심)
```

- 비밀정보 의심 파일 등 Step 2에서 제외한 파일은 "제외" 항목에 이유와 함께 표시한다.

### Step 6: 커밋 실행

계획한 커밋을 순서대로 실행한다.

```bash
git add -- <파일들>
git commit -m "<메시지>"
```

- 본문이 있는 메시지는 heredoc 등으로 줄바꿈을 보존해 전달한다.
- pre-commit hook이 실패하면 `--no-verify`로 우회하지 않는다. 원인을 사용자에게 보고하고, 수정 후 **새 커밋**으로 다시 시도한다(`--amend` 금지).
- 완료 후 `git log --oneline -n <커밋 수>`로 결과를 보여준다.

## 금지 사항

- `git push`, `--amend`, `--no-verify`, `git reset --hard` 등 되돌리기 어렵거나 기록을 바꾸는 명령 (사용자가 명시적으로 요청한 경우 제외)
- `git add .` / `git add -A`로 검토하지 않은 파일까지 한꺼번에 스테이징
- 대화형 명령(`git add -p`, `git rebase -i`)
